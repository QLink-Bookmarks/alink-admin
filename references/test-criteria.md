# 테스트 기준 작성

원본: `alink-channel/.agents/skills/issue-workflow/references/test-criteria.md`. React 웹의 관찰 가능한 결과를 기준으로 작성한다.

한 줄에 하나의 `- [ ]` 조건을 쓴다. 내부 함수·상태·HTTP 코드보다 사용자가 보는 동작을 적는다. 성공과 실패·재시도, 빈 상태와 검색 결과 없음, 입력 보존을 함께 다룬다. 해당 플랫폼만 적용되면 `— 웹 와이드` 또는 `— 웹 모바일`을 붙인다.

정상 경로, 입력 검증(한글 IME 포함), 상태(로딩·빈 상태·오류·권한·요청 실패), 경계값, 이동·복귀·직접 URL·새로고침, 반복 동작, 데이터 반영, 플랫폼 차이, 완성도를 빠짐없이 점검한다. 바뀌지 않는 기능의 무관한 테스트를 추가하지 않는다.

와이드 1280×800, 모바일 390×844, 경계 768×1024 및 769×1024에서 light/dark를 확인한다. 가로 넘침, 키보드·focus trap/복귀, 스크린리더 상태 알림, 입력 경계와 placeholder 대비, 최소 40px 터치 영역, safe-area를 확인한다. 네이티브 iOS/Android는 별도 React 웹이므로 범위 밖이며 웹 검사로 네이티브 통과를 주장하지 않는다.

Vitest는 순수 로직, Playwright는 사용자 흐름을 검증한다. 외부 Google/API 검증과 명시적 fixture 검증을 구분한다. 실행하지 못한 검사는 통과로 표시하지 않는다. 로그·캡처는 `output/`에 기록한다. PM harness에서는 캡처를 생성한 pane이 이미지를 열지 않고 reviewer가 검토한다.
